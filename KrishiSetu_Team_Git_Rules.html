Mandatory Protocol

KrishiSetu 🌾 — Team Git & GitHub Guidelines

Strict Collaboration Rules for All Team Members

⚠️ MANDATORY REQUIREMENT: Every team member MUST push and pull code to GitHub every day using proper conventional commit messages. No breaking changes or force pushes allowed.

1. Rule #1: ALWAYS PULL BEFORE STARTING WORK

Before editing any code on your local computer, you MUST pull the latest changes from GitHub:

git pull origin main

2. Rule #2: ALWAYS PUSH YOUR WORK WHEN DONE

Never keep your code only on your laptop. At the end of every work session, push to GitHub:

git add .
git commit -m "feat: add buyer order status table"
git push origin main

3. Rule #3: PROPER COMMIT MESSAGES ARE MANDATORY

Vague commit messages like "done", "update", or "asdf" are STRICTLY PROHIBITED. Use conventional commit prefixes:

Prefix Meaning Example Commit Message
feat: New feature / component git commit -m "feat: add crop search bar component"
fix: Bug fix git commit -m "fix: resolve navbar overlap on mobile"
docs: Documentation updates git commit -m "docs: update team git workflow rules"
style: CSS / Styling tweaks git commit -m "style: adjust padding on produce card"
refactor: Code cleanup git commit -m "refactor: clean up supabase client helper"
chore: Package / Config changes git commit -m "chore: add @supabase/ssr package"
📢 IMPORTANT NOTE FOR THE TEAM:
"Agar git commit, push, pull ya merge conflict me koi confusion hai, to IMMEDIATELY Meet pe pucho! Par bina pull/push kiye ya bina proper commit message ke kaam submit mat karo. Git workflow MANDATORY hai!"

4. Daily Step-by-Step Command Workflow

# Step 1: Start of Session (PULL latest code)
git pull origin main

# Step 2: Write & test your code

# Step 3: Check modified files
git status

# Step 4: Stage your changes
git add .

# Step 5: Commit with clear description
git commit -m "feat: add farmer registration form"

# Step 6: End of Session (PUSH to GitHub)
git push origin main
